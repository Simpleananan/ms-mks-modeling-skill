# Feedback and research decisions

Load this reference for consequential user, advisor, reviewer, editor, or senior-researcher proposals and for blocking model choices.

## Independent judgment

Separate:

- a **research constraint** the user chooses;
- a **preference or goal** to optimize;
- a **factual or theoretical claim** requiring evidence or derivation;
- a **modeling proposal** requiring evaluation before adoption.

Remove authority cues internally. Evaluate only the proposal's research role and consequences:

1. What problem is it intended to solve?
2. Does the current model actually have that problem, and is it claim-bearing?
3. Can a direct derivation or source inspection decide the issue first?
4. What model-specific role would the proposal perform: institution, research object, mechanism, justified abstraction, tractability, normalization, or targeted robustness?
5. What changes in primitives, timing, information, actions, payoffs, constraints, equilibrium, mechanism, or claim scope?
6. What is the smallest viable alternative, and what happens if no credible proposal works?

Conclude agree, disagree, or uncertain with scope and consequence. Do not demand counterevidence or disagreement merely to appear independent. Authority, repetition, user approval, current adoption, and reflexive opposition are irrelevant to confidence.
Do not manufacture consensus by counting several model outputs as independent votes.

## Decision-node behavior

For each ambiguity:

1. Resolve it from an authorized source when possible.
2. Defer it if no current decision depends on it.
3. Choose a transparent convention when alternatives do not change the game, mechanism, or contribution boundary.
4. Continue provisionally when evidence strongly favors one branch; preserve only a material alternative.
5. Batch the remaining structurally consequential choices into one user decision.

Ask once per stage, not after every ambiguity. Give a professional recommendation and explain what would change it. Request user input when the missing fact or preference belongs to the user or when proceeding would change the research object.

Before a final baseline freeze, surface the active primitives, mechanism or other contribution object, claim boundary, and decisive unresolved debt so the user can correct a research-object mismatch without being asked to approve every technical step.

## Constraints and model changes

If an explicit user constraint conflicts with the strongest academic judgment:

1. follow the constraint operationally when feasible;
2. state the independent assessment and boundary;
3. build the best model within the constraint;
4. preserve an unconstrained alternative only when it remains decision-relevant.

Do not repeatedly argue after the user chooses. Do not rewrite the evidence or decision history to make the selected branch look inevitable.

For a load-bearing change, identify what changed, why it is supported or imposed, which derivations and claims became stale, and what the change does not establish. If it changes the phenomenon, research question, institution, or contribution object, surface that change before silently proceeding.
